# CycleWise agent specs and policies

There are two Omnigent setups. **Use v2** unless you are reproducing the earlier result.

| Setup | Folder | Design | Revision trigger |
|---|---|---|---|
| **v2 (current)** | `omnigent/cyclewise_v2/` | Checkpoints at cycles 50, 100, 150 under a channel-cycle budget | Spearman(final score, log cycle life) on revealed cells **< 0.5**, allowed after **b1 and b2**, never on b3 |
| v1 (earlier) | `omnigent/cyclewise_lab/` | One decision at cycle 50 under a cell budget | precision@K < 0.5 or Spearman < 0.3, train batch only |

The v2 numbers come from `config/prereg_v2.yaml`, and the v2 tools enforce them. If this file and the tools ever disagree, the tools and the pre-registration are right.

## v2 agents (`omnigent/cyclewise_v2/`)

- **Supervisor:** `v2_start_run`, `v2_run_state`, `v2_request_approval` (gated by an ASK at every checkpoint), `v2_evaluate_run`. It passes the rule in force from batch to batch.
- **Evidence:** `v2_feature_catalog`, `v2_submit_hypothesis`. ΔQ variance (`dq_logvar`, direction −1) must be the base signal with the largest weight. The rule is fixed once a batch's first checkpoint runs.
- **Planner:** `v2_checkpoint_options`, `v2_submit_choice`. At each checkpoint it picks one of at least two options, all within budget; cell IDs come from the tool.
- **Runner:** `v2_execute_checkpoint`. It runs only an approved plan, once, in order.
- **Critic/Safety:** `v2_safety_scan`, `v2_submit_critique`. Revision is permitted when the trigger above fires on b1 or b2, at most once per batch, and is fit on revealed cells only.

## v1 agents (`omnigent/cyclewise_lab/`)

The sections below describe the earlier v1 setup.

The Omnigent definitions live in `omnigent/cyclewise_lab/`:

- `config.yaml` is the supervisor.
- `agents/<name>/config.yaml` defines each specialist.
- `**/tools/python/<tool>.py` holds the tools, one tool per file named after the tool (Omnigent 0.16 grants tools by file stem), with non-strict schemas so defaulted arguments stay optional. These files are generated by `omnigent/gen_tools.py` and delegate to `cyclewise/tools/omni_tools.py`.

The headless path (`cyclewise/run_loop.py`) uses the same tools, schemas, gates, and log.

## Supervisor: `cyclewise_lab`
Coordinates the loop and passes structured JSON between sub-agents (`sys_session_send` / `sys_read_inbox`). It does no analysis itself.
- **Tools:** `start_run`, `get_run_state`, `request_approval`, `evaluate_run`.
- **Policies:** `leakage_guard`, `reveal_gate`, `approval_gate` (ASK), `rate_limit` (80 tool calls).
- **Owns the approval request.** An ASK raised inside a sub-agent is never shown to the human, because sub-agents run headless. So the supervisor, whose session the human is watching, calls `request_approval` for each plan.

## Evidence
- **Decides:** which early signals to trust.
- **Sees:** cycles ≤ 50 only, no labels.
- **Tools:** `list_cells`, `early_feature_summary`, `query_early_cycles`, `list_citations`, `submit_hypothesis`.
- **Output:** `Hypothesis` with 1–6 catalog features (sign, weight in (0, 3]), a rationale, citations from `CITATIONS.md` only, and `label: "agent-generated"`.
- **Rejected:** unknown features or citations, which the agent then retries.
- **Policies:** `leakage_guard`, `rate_limit`.

## Planner
- **Decides:** which test to run within the budget (cells).
- **Tools:** `check_budget`, `preview_ranking`, `submit_test_plan`. The supervisor requests approval.
- **Strategies:**
  - `exploit_top_k`: keep the top-scoring cells.
  - `explore_stratified`: keep the top cells plus some spread across the score range, to learn for a revision.
  - `hedge_with_dq`: half from the rule, half from the ΔQ ranking.
- **Output:** a `TestPlan` with **≥ 2 options**, the chosen option, `cost_cells`, `expected_learning`, and `cell_ids`. Cell IDs are filled in by tools from the rule, so the LLM never writes cell IDs.
- **Rejected:** fewer than 2 options, `chosen` not among the options, or over budget.
- **Rejection path:** a human rejection triggers one re-proposal with the note. A second rejection stops the run.
- **Policies:** `leakage_guard`, `budget_guard`, `rate_limit`.

## Runner
- **Decides:** nothing; it executes.
- **Tool:** `execute_plan`, which commits the selection (IDs + hash), reveals the kept cells (requires commit + approval for this plan), and logs an MLflow run.
- **Output:** `Result`.
- **Policies:** `leakage_guard`, `reveal_gate`, `rate_limit`.

## Critic / Safety
- **Safety mode:** `safety_scan` flags hot cells (early Tmax z > 3), IR jumps (> 2 mΩ), and missing sensors. Flags go to the human approval screen; they are never silently dropped or kept.
- **Critic mode:** `submit_critique`. Revision is allowed only if the **pre-registered trigger** fires on the train batch (precision@K < 0.5 or Spearman on revealed cells < 0.3), at most once per batch.
- **Revised rule:** an executable ridge model on log10 cycle life, fit on **revealed batch-1 cells only**, with alpha chosen by leave-one-out on those cells. It is validated as executable before use.
- **Output:** `Critique` (with `next_experiment`).
- **Policies:** `leakage_guard`, `rate_limit`.

## Policies (`cyclewise/policies/omni_policies.py`)
| Policy | Event | Decision |
|---|---|---|
| `leakage_guard` | any tool call | DENY if any `cycle`/`min_cycle`/`max_cycle`/… argument > 50 or non-integer, or any argument names `labels_hidden`, `cycles_raw`, the hidden DB, or the frozen threshold |
| `approval_gate` | `request_approval` | ASK a human, showing the chosen option, alternatives, cost, cells, and safety flags. Never auto-approves |
| `reveal_gate` | `execute_plan` | DENY unless the research log holds an `approved` approval for that exact plan |
| `budget_guard` | `submit_test_plan` | DENY if any option exceeds the cell budget |
| `rate_limit` | any | built-in `max_tool_calls_per_session` (80) |

On a shared server, register them with `omnigent server -c omnigent/server.yaml`.

## LLM behaviour rules (`cyclewise/agents/llm.py`)
- **Validation and retries:** JSON is validated by Pydantic plus domain checks. On failure the agent retries up to 2 times with the validation error in the prompt, then falls back to a deterministic policy, logged as `fallback_used=true`.
- **Model:** `claude-opus-5` by default (`CYCLEWISE_MODEL` to override).
- **Limits:** per-call timeout, SDK retries with exponential backoff, and at most 60 LLM calls per run.
- **Caching:** responses are cached by input hash, so replays are free and deterministic.
